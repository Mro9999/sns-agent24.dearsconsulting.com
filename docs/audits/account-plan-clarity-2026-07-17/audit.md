# ログイン・現在プラン表示 監査記録

実施日: 2026-07-17
対象: `https://sns-agent24.dearsconsulting.com/app`

## 改善前

- ログイン状態はアバターだけで示され、ログイン中かどうかと利用者名が判別しづらかった。
- 現在プランは押せないボタンのように見え、情報表示なのか操作なのかが曖昧だった。
- 利用者を識別する名前・メールアドレスが画面上に表示されていなかった。

## 改善後

- ヘッダーに「ログイン中」、利用者名、メールアドレスを常時表示した。
- `/api/user/status` の結果を優先して「Free / Pro / Pro Max / 運営者」を現在プランとして表示した。
- プラン確認中はFreeと誤表示せず「プランを確認中」と表示した。
- プラン情報を非操作のセクションに分離し、利用可能な場合だけ「プラン管理」をボタンとして表示した。
- 主要リンクとボタンの最小高さを44pxにし、キーボードフォーカスを見えるようにした。
- ログイン状態を色だけに頼らず文字でも示し、セクションへアクセシブルな名前と更新通知を付けた。
- 未ログイン状態では読み込み表示を残さず「ログイン」ボタンを表示した。

## 検証結果

- ログイン済み運営者アカウントで、利用者名・メールアドレス・「運営者アカウント」の同時表示を確認した。
- アカウントメニューから「アカウントの管理」「サインアウト」へ進めることを確認した。
- 投稿作成、履歴、承認の3画面で同じログイン情報・現在プランを表示する共通部品へ移行した。
- 3画面すべてで「運営者アカウント」まで確定表示され、承認画面でもアカウントメニューを開けることを確認した。
- 本番カスタムドメインへの割り当てとトップページHTTP 200を確認した。
- `test:account-status`、`test:billing`、`test:copy-safety`、`lint`、`build`、`test:vercel-trace` はすべて成功した。

## 契約プランと利用権限の分離

- 「契約プラン」は、SNS Agent24用として登録されたStripe料金IDと一致する契約だけを根拠に表示するよう変更した。
- 「利用権限」はClerkの権限として別表示し、運営者権限をPro / Pro Max契約として扱わないようにした。
- 契約状態として、契約中、無料トライアル中、支払い方法の確認が必要、解約予定、解約済み、有料契約なし、確認できない状態を区別した。
- 解約予定の場合は利用期限を、継続契約の場合は次回更新日を表示できるようにした。
- Stripe照合に失敗した場合はFreeと断定せず、「契約プランを確認できません」と表示する。
- 本番のログイン済み運営者アカウントでは「契約プラン: Freeプラン・有料契約なし」「利用権限: 運営者」と表示された。SNS Agent24用と確認できない別商品の支払いは契約プランへ含めていない。
- 投稿作成、履歴、承認の3画面で同じ表示を確認した。
- 初回の本番確認で、料金表だけが利用権限をPro契約として扱う不整合を検出した。料金表も契約プランを基準に修正し、Freeだけが「現在のプラン」、Proは「Proにアップグレード」と表示されることを確認した。
- 最終本番デプロイ `dpl_CCu9XX5KaTHfiBhg9TBjzkAcNwmo` はReadyでカスタムドメインへ割り当て済み。`/api/user/status` はHTTP 200、直近のerrorログと5xxログは0件だった。
- 契約・決済・Stripeイベント、承認・却下・公開操作は変更していない。

## 画像生成Routeの公開阻害要因と解消

- 修正前は、承認画面で画像未生成の投稿を処理すると `POST /api/generate-post-image` がHTTP 500になっていた。
- 原因は `next/dist/compiled/@vercel/og/index.node.js` がVercel Functionのバンドルに含まれず、オーバーレイ合成とテキストフォールバックの両方が失敗していたことだった。
- `next.config.js` の `outputFileTracingIncludes` で、このRouteに必要なNext.js同梱のOG実行ファイルを明示的に含めた。
- `test:vercel-trace` を追加し、`index.node.js`、`resvg.wasm`、`yoga.wasm`、日本語フォント2件がビルド出力に含まれることを自動検証した。
- 本番デプロイ `dpl_3oWoQSNgyFU6hSvx3fV93pURjLK8` で、5回の `POST /api/generate-post-image` がすべてHTTP 200になったことを確認した。
- 承認画面を再読込し、5投稿・15画像がDBから復元され、失敗表示0件、5投稿すべての承認ボタンが有効になることを確認した。承認・却下・公開操作は行っていない。
- 同デプロイの直近errorログと5xxログは0件で、`https://sns-agent24.dearsconsulting.com/` はHTTP 200を返した。

画面比較用スクリーンショットにはログイン利用者の情報が含まれるため、目視確認後はGit管理対象から除外した。
